## 🔬 Overview

I2C is a widely used two-wire serial communication protocol for short-distance communication between integrated circuits. This project implements a complete I2C Master and Slave with full verification environment.

**Key Features:**
- 100 kHz standard mode I2C
- 7-bit addressing
- Read and write operations
- Clock stretching support
- Acknowledge handling
- Complete UVM-style verification

---

## 📡 I2C Protocol

### Signals
- **SCL** - Serial Clock (generated by master)
- **SDA** - Serial Data (bidirectional, open-drain)

### Protocol Sequence
1. **START** - SDA falls while SCL high
2. **Address + R/W** - 7-bit address + 1-bit operation
3. **ACK** - Slave acknowledges
4. **Data** - 8-bit data transfer
5. **ACK/NACK** - Acknowledge
6. **STOP** - SDA rises while SCL high

## 🏗️ Architecture

```
┌─────────────┐                    ┌─────────────┐
│  I2C Master │─── SCL ────────────▶│  I2C Slave  │
│             │◀── SDA ────────────▶│             │
└─────────────┘                    └─────────────┘
      │                                   │
   newd, addr                         128-byte
   din, op                             Memory
   dout, done
```

### Master Features
- Generates SCL (100 kHz from 40 MHz system clock)
- Handles START/STOP conditions
- Manages ACK/NACK
- Supports read and write operations

### Slave Features
- 128-byte internal memory
- Address decoding
- ACK generation
- Data read/write

## ⚙️ Design Features

### Master FSM States
1. **IDLE** - Wait for new transaction
2. **START** - Generate start condition
3. **WRITE_ADDR** - Send 7-bit address + R/W
4. **ACK_1** - Wait for slave ACK
5. **WRITE_DATA** - Transmit data
6. **READ_DATA** - Receive data
7. **ACK_2** - Check ACK
8. **MASTER_ACK** - Send ACK/NACK
9. **STOP** - Generate stop condition

### Clock Generation
- System clock: 40 MHz
- I2C clock: 100 kHz
- 4x oversampling for precise timing

## 🧪 Verification Environment

### Class-Based Architecture

**Transaction Class**
- Random address (2-4), data (2-9)
- Read/write operation randomization (50/50)
- Contains all I2C signals

**Generator**
- Creates 20 random transactions
- Sends to driver via mailbox
- Synchronizes with scoreboard

**Driver**
- Drives master inputs (newd, addr, din, op)
- Waits for done signal
- Handles reset sequence

**Monitor**
- Samples DUT outputs on done
- Captures read data
- Sends to scoreboard

**Scoreboard**
- Maintains reference memory model (128 bytes)
- Compares expected vs actual data
- Reports PASS/FAIL for each transaction

### Test Flow
```
Generator → Driver → DUT → Monitor → Scoreboard
              ↓                         ↑
           Mailbox                  Mailbox
```

## 🚀 Getting Started

### Prerequisites
- ModelSim / QuestaSim / Vivado
- SystemVerilog support

### Simulation

```bash
# Clone repository
git clone https://github.com/YOUR_USERNAME/I2C-Verification.git
cd I2C-Verification/sim

# Run simulation
make run

# Or manually:
vlib work
vlog -sv ../src/*.v ../tb/*.sv
vsim -c work.tb -do "run -all"
```

### Expected Output
```
[DRV] : RESET DONE
---------------------------------
[GEN]: op :0, addr : 3, din : 7
[DRV] : OP: WR, ADDR:3, DIN : 7
[MON] op:0, addr: 3, din : 7, dout:0
[SCO]: DATA STORED -> ADDR : 3 DATA : 7
-----------------------------------------------
[GEN]: op :1, addr : 3, din : 5
[DRV] : OP: RD, ADDR:3, DOUT : 7
[MON] op:1, addr: 3, din : 0, dout:7
[SCO] :DATA READ -> Data Matched exp: 7 rec:7
```
